KEY OBSERVATIONS
=================

1. DISPATCH REUSE: Compiler shares 8+ dispatch kernels between prefill and decode
   (prefill_dispatch_13, 24, 33, 34, 35, 36, 37, 39, 44, 45, 46 all used in decode too)

2. "D" MEANS DYNAMIC: Every dispatch with "D" in its shape resolves that dim at
   invocation time. In prefill D typically = batch×S, in decode D typically = batch (=1).

3. slow_memcpy: KV cache scatter/gather uses "slow_memcpy" dispatches — NOT optimized
   kernels. These are element-by-element copies through the paged block structure.
   Prefill scatters S entries (S dispatch calls in a loop!), decode scatters 1.

4. ATTENTION IS FUSED: QK^T + softmax + AV is ONE dispatch (dispatch_28 for prefill,
   dispatch_33 for decode). BUT it materializes the full S×S attention matrix — no
   flash attention tiling.

5. MoE SCALING: Expert gather creates [8×D, 1024, 2048] gathered weights.
   At S=1024: 8192 × 1024 × 2048 × 4 bytes = ~67 GB of gathered weight data per layer.
   The transpose_2097152x64 dispatch (static, no D) runs 3× per layer for gate/up/down.

6. LAYER LOOP: The compiler keeps scf.for over 16 layers (not unrolled), but DOES
   unroll parameter selection into pairs of 2 using i1 flags (even/odd layer trick).

7. RESIDUAL FUSION: O projection (dispatch_31 prefill, dispatch_35 decode) has the
   residual add FUSED into the matmul dispatch. Same for decode norm (dispatch_13).
